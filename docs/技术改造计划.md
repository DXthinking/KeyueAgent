### 4.1 OrderQueryTool 多级缓存

```java
@Tool(description = "Query all orders for a specific user. Checks L1 Caffeine cache first, then L2 Redis cache, finally MySQL.")
public String queryUserOrders(@ToolParam(description = "用户ID") String userId) {
    String l1Key = "user_orders:" + userId;

    // L1 Caffeine
    Object l1Cached = userOrdersCache.getIfPresent(l1Key);
    if (l1Cached != null) {
        return buildOrderListResponse((List<Order>) l1Cached, "L1缓存获取用户订单");
    }

    // L2 Redis
    Object l2Cached = redisTemplate.opsForValue().get(l1Key);
    if (l2Cached != null) {
        userOrdersCache.put(l1Key, l2Cached);  // 回填 L1
        return buildOrderListResponse((List<Order>) l2Cached, "L2缓存获取用户订单");
    }

    // MySQL
    LambdaQueryWrapper<Order> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(Order::getUserId, userId).orderByDesc(Order::getCreatedAt);
    List<Order> orders = orderDao.selectList(wrapper);

    // 写入 L1 + L2
    userOrdersCache.put(l1Key, orders);
    redisTemplate.opsForValue().set(l1Key, orders, 5, TimeUnit.MINUTES);

    return buildOrderListResponse(orders, "从数据库获取用户订单");
}
```

### 4.3 HybridSearchService — 向量+BM25+RRF 融合检索（核心新增）

这是对原版 PolicySearchTool 的升级。原版只有向量检索，改造后变为混合检索。

#### 实现逻辑

```java
@Service
public class HybridSearchService {

    @Autowired
    private VectorSearchService vectorSearchService;  // 向量检索（Milvus）

    @Autowired
    private VectorEmbeddingService embeddingService;  // 向量化

    @Autowired
    private ElasticsearchOperations esOperations;      // ES 操作

    private static final int TOP_K = 3;
    private static final int RRF_K = 60;  // RRF 常数

    /**
     * 混合检索：向量检索 + BM25 关键词检索 + RRF 融合
     */
    public List<SearchResult> hybridSearch(String query) {
        // 1. 向量检索（Milvus）
        List<SearchResult> vectorResults = vectorSearchService.searchSimilarDocuments(query, TOP_K);

        // 2. BM25 关键词检索（Elasticsearch）
        List<SearchResult> bm25Results = bm25Search(query, TOP_K);

        // 3. RRF 倒数排名融合
        return rrfFuse(vectorResults, bm25Results, TOP_K);
    }

    /**
     * BM25 关键词检索
     * 从 ES 的 policy-doc 索引中按关键词匹配
     */
    private List<SearchResult> bm25Search(String query, int topK) {
        NativeQuery esQuery = NativeQuery.builder()
            .withQuery(q -> q
                .match(m -> m
                    .field("content")
                    .query(query)
                )
            )
            .withMaxResults(topK)
            .build();

        SearchHits<PolicyDoc> hits = esOperations.search(esQuery, PolicyDoc.class);
        List<SearchResult> results = new ArrayList<>();
        hits.forEach(hit -> {
            SearchResult sr = new SearchResult();
            sr.setContent(hit.getContent().getContent());
            sr.setScore(hit.getScore().floatValue());
            results.add(sr);
        });
        return results;
    }

    /**
     * RRF（Reciprocal Rank Fusion）倒数排名融合
     * 公式：score(d) = Σ 1/(k + rank_i(d))
     * k=60 是标准常数，rank_i(d) 是文档 d 在第 i 路检索结果中的排名（从1开始）
     */
    private List<SearchResult> rrfFuse(List<SearchResult> vectorResults,
                                        List<SearchResult> bm25Results,
                                        int topK) {
        Map<String, Double> rrfScores = new HashMap<>();
        Map<String, SearchResult> contentMap = new HashMap<>();

        // 向量检索结果排名
        for (int i = 0; i < vectorResults.size(); i++) {
            String content = vectorResults.get(i).getContent();
            int rank = i + 1;
            double score = 1.0 / (RRF_K + rank);
            rrfScores.merge(content, score, Double::sum);
            contentMap.putIfAbsent(content, vectorResults.get(i));
        }

        // BM25 检索结果排名
        for (int i = 0; i < bm25Results.size(); i++) {
            String content = bm25Results.get(i).getContent();
            int rank = i + 1;
            double score = 1.0 / (RRF_K + rank);
            rrfScores.merge(content, score, Double::sum);
            contentMap.putIfAbsent(content, bm25Results.get(i));
        }

        // 按 RRF 分数排序，取 topK
        return rrfScores.entrySet().stream()
            .sorted(Map.Entry.<String, Double>comparingByValue().reversed())
            .limit(topK)
            .map(e -> {
                SearchResult sr = contentMap.get(e.getKey());
                sr.setScore(e.getValue().floatValue());
                return sr;
            })
            .collect(Collectors.toList());
    }
}
```

## 七、SSE + Reactor Flux 流式输出深度设计

### 核心实现

```java
// ChatController.chatStream()
SseEmitter emitter = new SseEmitter(300000L);  // 5 分钟超时

Flux<NodeOutput> stream = agent.stream(question);  // ReactAgent 流式调用

stream.subscribe(
    output -> {                              // onNext：每收到一个 chunk
        if (output instanceof StreamingOutput streamingOutput) {
            OutputType type = streamingOutput.getOutputType();
            if (type == OutputType.AGENT_MODEL_STREAMING) {
                String chunk = streamingOutput.message().getText();
                fullAnswerBuilder.append(chunk);     // 累积完整答案
                emitter.send(SseEmitter.event()
                    .name("message")
                    .data(SseMessage.content(chunk), MediaType.APPLICATION_JSON));
            }
        }
    },
    error -> {                               // onError：异常处理
        emitter.send(SseMessage.error(...));
        emitter.completeWithError(error);
    },
    () -> {                                  // onComplete：流结束
        session.addMessage(question, fullAnswerBuilder.toString());
        persistChatMessage(...);              // 异步持久化
        emitter.send(SseMessage.done());
        emitter.complete();
    }
);
```

### 流式输出的关键设计点

| 设计点 | 说明 |
|--------|------|
| `SseEmitter` 超时 | 5 分钟（300000ms），覆盖长对话 + 多轮工具调用 |
| `fullAnswerBuilder` | 线程安全累积完整答案，流结束后一次性持久化 |
| `onNext` 过滤 | 只转发 `AGENT_MODEL_STREAMING` 类型，工具调用结果不直接推给前端 |
| `onError` | 异常时先推 error 事件再 `completeWithError`，前端能收到友好提示 |
| `onComplete` | 流结束后持久化对话 + 发 done 事件 + `complete()` 关闭连接 |
| 异步持久化 | 对话消息通过 MQ 异步落库，不阻塞 SSE 响应 |

### 潜在问题与优化方向

| 问题 | 风险 | 优化方案 |
|------|------|---------|
| `StringBuilder` 非线程安全 | 多线程 subscribe 回调可能并发追加 | 改用 `StringBuffer` 或 `StringBuilder` 配合同步块 |
| `emitter.send()` 可能抛异常 | 客户端断开后 send 抛 `IOException` 未捕获 | 加 try-catch，捕获后 `emitter.complete()` |
| 工具调用结果不透明 | 前端看不到 Agent 调用了哪些工具 | 新增 `tool_call` 事件类型，推送工具名+参数+结果摘要 |
| 流中断无重连 | 网络波动导致 SSE 断开后无法续传 | 前端实现 EventSource 自动重连 + 后端支持 `Last-Event-ID` |
| 背压未处理 | LLM 输出过快时 `emitter.send` 可能阻塞 | 用 `Flux.onBackpressureBuffer` 或 `onBackpressureDrop` |
| 超时时间固定 | 复杂多 Agent 分诊可能超 5 分钟 | 根据接口类型动态设置超时（chat 5min，ai_ops 10min） |
| 异常信息泄露 | `completeWithError(error)` 可能把堆栈推给前端 | 统一包装为友好错误消息，不暴露内部异常 |
